## Real SPY frames (`optionsdx-spy-4dates.json`)

**Source.**
- OptionsDX end-of-day SPY option quotes, obtained through the Kaggle dataset
  [`dudesurfin/spy-options-eod-volatility-surface-2010-2023`](https://www.kaggle.com/datasets/dudesurfin/spy-options-eod-volatility-surface-2010-2023).
  Kaggle lists the dataset's `licenseName` as MIT.
- The OptionsDX terms page, <https://www.optionsdx.com/terms-of-service/>, returned HTTP 404 when checked on 2026-10-29. So **no OptionsDX
  terms text is known**, and we cannot name the terms these values are shared on. The numbers are OptionsDX's, so we treat them as vendor
  data and publish only values derived from them.
- The implied vols were computed by the pricing build of [vol-strategy-backtester](https://github.com/rajib2k5/vol-strategy-backtester)
  (MIT, Rajib Bahar). That build read smiles built from the de-Americanised out-of-the-money quotes on a fixed grid of log-moneyness and
  days to expiry. The file here holds the grid it produced. The values are copied; nothing is recomputed here.
- Source file: `app/public/data/surface_frames.json` of vol-strategy-backtester, working tree based on commit
  `35cb68269034d995e39f17d63bc907f5779ed5b4` with local changes (the file is untracked there). The same string is in `source.source_commit` of
  the JSON, with a `-dirty` suffix. The run ids (`run_id`, `config_hash`, `data_fingerprint`) are in `source.run`.
  Re-create the file with `npm run import:real -- --in <path to that file>`.

**What is in the file.** Per date: the IV grid (26 log-moneyness k in [-0.30, 0.20] step 0.02, by 11 expiries of 7 to 365 days), the
`cell_flags` bitmask grid, and `quoted_share`. Dates: 2017-11-03, 2018-02-05, 2020-03-16, 2023-06-15. Labels and events are our own words
("calm, late 2017", "February 2018 volatility spike", "March 2020 crash", "mid-2023").
No quote row, price, strike list or chain is in it. Raw vendor files (CSV, Parquet, DuckDB, DoltHub clones) are never copied into this
repository. The committed file is about 43 KB.

**What is not imported, and why.** The source file also holds `spot` (the SPY close, from Yahoo Finance), `vix_close` (the Cboe VIX close) and
`atm_iv_30d`. The player does not use them, so they are not imported. Yahoo's terms allow personal use. Cboe's website terms need Cboe's prior
written consent to publish or distribute its data. The VIX closes are therefore left out, and no event or label text quotes a Cboe figure.
A test (`scripts/import/committed.test.ts`) scans the committed file for the source's spot and VIX numbers, as values and inside strings. It
reads the source's `spot` and `vix_close` at test time from `surface_frames.json` in vol-strategy-backtester (override the path with the
`VSC_SOURCE_FRAMES` environment variable) and compares them as numbers, so `9.140` and `9.14` match. The test file holds no source value, not even
as a hash. On a fresh clone the source file is absent and that test is skipped, with the reason in its name.

**Hashes in history.** An earlier version of that test held unsalted SHA-256 hashes of those 8 values. Commit `5bfa0c0` still contains them.
Short decimals brute-force in a fraction of a second, so the hashes are reversible and that history effectively contains the 8 values.
Git history is never rewritten (owner rule), so they stay there.

**First commit anywhere.** In vol-strategy-backtester this file is untracked: it is not in `git ls-files` and not in origin/main `35cb682`.
Committing it here is the first time these values enter any git history. This repository is private. Whether and when it becomes public is the
owner's decision. Git history is never rewritten, so once committed the file stays in history. If the owner rules the derived OptionsDX values
out, the file is removed going forward with a normal commit (design §17).

**How the page shows it.**
- The badge, always on screen: "SPY implied vols derived from OptionsDX quotes (via Kaggle). Interpolated between dates."
- The 4 dates are months to years apart. Between two dates the frames are **interpolated** (linear in total variance, per cell), not observed.
  The caption reads `2018-02-05 → 2020-03-16 (interpolated)` for the whole transition. A date alone is shown only while that date's own
  grid is on screen (the hold).
- A second line shows "N% of cells extrapolated", from 1 - `quoted_share`: 35% (2017-11-03), 34% (2018-02-05), 1% (2020-03-16),
  15% (2023-06-15). In a transition it shows both ends, for example "34% → 1%".
- The data is shown as exported. It is **not** arbitrage-repaired here.

### No-arbitrage screens on the real frames (measured, not enforced)

Run by `npm run import:real` and pinned by `scripts/import/committed.test.ts`, so these numbers cannot go stale unnoticed.
The synthetic story passes the same screens with 0 violations (15 600 calendar pairs, 15 840 butterfly cells, min g 0.30).

| Date | Calendar: cells where total variance falls with expiry | Butterfly: interior cells with g < 0 | Min g |
|---|---|---|---|
| 2017-11-03 | 0 of 260 | 18 of 264 | -0.77 |
| 2018-02-05 | 0 of 260 | 28 of 264 | -3.25 |
| 2020-03-16 | 0 of 260 | 82 of 264 | -10.87 |
| 2023-06-15 | 0 of 260 | 27 of 264 | -1.80 |
| all four | **0 of 1040** | **155 of 1056 (14.7%)** | -10.87 |

- **Calendar: clean, but not by luck.** The source build already adjusted cells to remove calendar arbitrage (flag bit 8,
  `SURFACE_CALENDAR_ADJUSTED`): 67, 80, 28 and 24 cells per date. So "0 violations" describes the grid as exported, after that adjustment,
  and not the raw quotes. In-between frames (3 pairs, 101 alphas each) also have 0 calendar violations, as the design predicts for a convex mix
  in total variance.
- **Butterfly: violations are present.** Gatheral's `g(k) >= 0` is checked with three-point finite differences on the k grid (step 0.02),
  at the 24 interior strikes of each of the 11 expiries. This is a screen, not a proof: on a noisy grid with a coarse k step, finite-difference
  `w''` is noisy, and a few very negative g values (min -10.87 on 2020-03-16, where nearly every cell is quoted) come from sharp kinks in the
  smile, not from extrapolation. Only 31 of the 155 violating cells are in cells flagged as strike-extrapolated (11, 9, 0, 11 per date).
  The check is validated on known cases (`src/lib/gridChecks.test.ts`: an SSVI grid agrees with the analytic g; the known-bad control
  η(1+|ρ|) = 5, θ = 0.02 is flagged). Butterfly is not enforced on these frames (design §5.2). Read the surface as market-derived and noisy.

## Synthetic frames (`synthetic-regime-story.json`)

Generated by this repository (`scripts/generate-synthetic.ts`, seed 20301) from a seeded SSVI model on fictional 2030 dates, and checked
against Gatheral and Jacquier's no-arbitrage conditions (design §5). It is not market data and is MIT like the code.

## Never committed

The downloaded vendor files themselves: Kaggle or OptionsDX CSV and Parquet, DoltHub clones, DuckDB stores. Only small derived grids, with
a notice naming each source and its terms.
